HIERARCHICAL NAVIGATION SYSTEM:

NEW ADVANCED NAVIGATION - Use these operations for better player experience:

Entry Connections: {"op": "set_entry_from", "data": {"location": "B", "from": "A"}} - Set that location B can be entered from location A
Clear Entry: {"op": "clear_entry_from", "data": {"location": "B"}} - Remove entry connection from location B
Default Entry: {"op": "set_default_entry", "data": {"container": "A", "entry": "B"}} - Where player goes when ENTERING container A

HOW THE NEW NAVIGATION WORKS:

1. **Entry Connections** (Many-to-Many): Multiple destinations available from current location
   - From Kitchen: can go to Living Room, Dining Room, Backyard
   - From Neighborhood: can go to House 1, House 2, Central Park

2. **Exit Connections** (One-to-One): Single path when leaving current location
   - Leave Kitchen → go to Hallway
   - Leave Neighborhood → go to City Center

3. **Default Entry for Containers**: Where you go when entering a container
   - Enter House → automatically go to Front Door or Living Room
   - Enter Neighborhood → automatically go to Main Street

NAVIGATION DESIGN PRINCIPLES:

- **Containers organize spaces**: Neighborhoods contain houses, houses contain rooms
- **Entry connections define movement options**: Where can I go from here?
- **Exit connections define departure**: How do I leave this area?
- **Hierarchical flow**: Enter container → default entry location → explore via entries → exit when done

PLAYER EXPERIENCE PSYCHOLOGY:

Understanding how navigation affects player emotions and immersion:

ENTRY CONNECTIONS - Discovery & Choice Emotions:
😊 **2-3 entry options** = Discovery excitement ("What's through here?")
😐 **1 entry option** = Linear progression (focused but safe)
😰 **5+ entry options** = Choice overload (decision paralysis, overwhelming)
😱 **0 entry options** = Trapped anxiety ("How do I get out?")

EXIT CONNECTIONS - Psychological Safety:
✅ **Always present** = Secure feeling ("I can always leave")
❌ **Missing** = Claustrophobic anxiety ("I'm trapped!")

DEFAULT ENTRY - Immersion Maintenance:
🎭 **Realistic entry** = Immersion preserved (enter house → front door)
💥 **Missing/illogical** = Immersion break (magically appear in bedroom)

NESTING - Spatial Context & Emotional Anchoring:
🏠 **Proper hierarchy** = Grounded feeling ("I understand where I am")
❓ **Wrong/missing** = Spatial confusion ("Where am I in relation to everything?")

COGNITIVE LOAD GUIDELINES:
- **Simple areas**: 1-2 exits (shops, bedrooms) = focused experience
- **Hub areas**: 3-4 exits (living rooms, town squares) = comfortable exploration
- **Complex areas**: 5+ exits only for major hubs (cities, dungeons) = overwhelming unless expected

IMMERSION PATTERNS:
- **Believable flow**: Bedroom → Hallway → Living Room → Front Door → Street
- **Breaks immersion**: Bedroom → directly to Neighborhood (skips logical steps)
- **Natural exits**: Kitchen → Dining Room (logical) vs Kitchen → Attic (confusing)

ASK YOURSELF - PLAYER EXPERIENCE QUESTIONS:
1. "What emotion do I want the player to feel in this space?"
2. "Should this encourage exploration (more entries) or focus (fewer entries)?"
3. "Will the player feel safe (exit available) or trapped (no exit)?"
4. "Does this navigation pattern feel realistic and believable?"
5. "Am I overwhelming the player with too many choices or boring them with too few?"

NAVIGATION RULES (SINGLE-INBOUND MODEL):

When a container has a default entry (like Home → Living Room):

✅ CORRECT: Connect rooms to the hub INSIDE the container (one-way)
   - Kitchen entry_from Living Room (both inside Home)
   - Bathroom entry_from Living Room (both inside Home)
   - {"op": "set_entry_from", "data": {"location": "Kitchen", "from": "Living Room"}}

❌ WRONG: Connect to the container or set reverse links on default entry
   - Kitchen entry_from Home (FAILS - Home has default entry)
   - {"op": "set_entry_from", "data": {"location": "Living Room", "from": "Kitchen"}} (FAILS - default entry cannot have entry_from)

UNDERSTANDING DEFAULT ENTRIES:
- When player enters Home → automatically goes to Living Room
- Do not set entry_from on default entry locations
- Rooms connect to the hub (e.g., Living Room), not to the container

WHEN OPERATIONS FAIL - UNDERSTAND THE ERROR:

"Cannot set direct entry from container"
→ The container has a default entry. Connect to rooms inside it instead.

"Default entry cannot have entry_from"
→ Don't try to set entry_from on default entry locations.

"Container with default entry cannot have entry_from"
→ Use connections between rooms inside the container.

Example Recovery:
If "Kitchen.entry_from = Home" fails with "Cannot set direct entry from container"
→ Try: "Kitchen.entry_from = Living Room" (connect to the default entry room)

HOW WORLD OPERATIONS BECOME TWEE GAMEPLAY (one-way model):

Understanding the critical translation from abstract world operations to concrete player experience:

ENTRY_FROM → CLICKABLE NAVIGATION:
- `{"op": "set_entry_from", "data": {"location": "Kitchen", "from": "Living Room"}}`
- Becomes: a clickable navigation option to Kitchen from the hub (generator dependent)
- Player sees: "Available destinations:" with bulleted clickable options
- Psychology: Each entry = one navigation choice (2-3 = comfortable, 5+ = overwhelming)

REVERSE TRAVEL → IMPLIED VIA DEFAULT ENTRY:
- No mirrored `entry_from` is needed back to the hub; exiting a container routes to its default entry

DEFAULT ENTRY → SEAMLESS CONTAINER FLOW:
- `{"op": "set_default_entry", "data": {"container": "House", "entry": "Living Room"}}`
- Becomes: `[[Enter House->Location_Living_Room]]` (jumps directly to room)
- Player sees: "Enter House" → automatically goes to Living Room (not generic House page)
- Psychology: Maintains immersion with realistic entry flow

NESTING → SPATIAL CONTEXT:
- `{"op": "nest", "data": {"child": "Kitchen", "parent": "House"}}`
- Becomes: Spatial organization (Kitchen exists inside House concept)
- Player sees: Contextual understanding of "where am I in the world"
- Psychology: Provides spatial grounding and logical organization

CONTAINER STATUS → HIERARCHICAL OPTIONS:
- `is_container: true` + `default_entry_location`
- Becomes: "Enter [Container]" links that provide deeper exploration
- Player sees: Ability to go "into" spaces rather than just "between" spaces
- Psychology: Creates depth and exploration layers
