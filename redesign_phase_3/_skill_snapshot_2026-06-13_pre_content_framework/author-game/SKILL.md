# Author Game — the 7-step authoring pipeline

Drives game authoring as a **7-step pipeline** (fantasy → seed → top-level → casting → NPC arcs → roster →
authoring), run **incrementally**: after the seed, the game is built **one verified piece at a time**, with
the user steering at the crucial forks and **nothing invented blind**. This replaces blind one-shot
generation (whole book + whole TOML in one unsupervised pour), which is where every structural bug — and
every "structurally correct but soulless" game — hid until the 300KB end.

This skill is **patterns, not code.** You (the agent) do the authoring and bookkeeping with your normal
tools (Read / Write / Edit / Bash). There is no helper module to call.

**The user's review surface is the DESIGN BOOK, not the TOML.** The user reviews *intent* in plain language
(`design_book.md`); the engine layer is the faithful translation of a design they already saw. This is the
**what-before-how** split made into a process rule (see `references/run-mode.md`).

## State (per game, under `games/<slug>/`)
- `design_book.md` — intent: the fantasy, the engine/economy/desire-ladder/frontier, **the machine** (the
  cross-wiring — core loop + which arcs wire to which / to the economy; a `## The machine` section, core loop
  set at Step 2, synthesized from every arc's §8 by Step 4/5), the cast + per-NPC briefs, the content roster.
  **Grown one section per step.** The thing the user reviews.
- `authoring_state.json` — the ledger: `pipeline_phase` (which step we're in — the dispatch reads THIS) +
  `npcs` (per-NPC budgets) + `structure_registry` + `plan` + `next_up` + `decisions_log`. **Created at the
  seed step** carrying `pipeline_phase`; `structure_registry`/`plan` stay empty until authoring. Shape +
  invariants: `references/ledger-schema.md`.
- `toml_phases/*.toml` — built content (authoring step only). `7_final_game.toml` is GENERATED by merge —
  never hand-edit it.

## The pipeline (each step → its reference → what it writes)
| `pipeline_phase` | Step | Reference | Output (into `design_book.md` unless noted) |
|---|---|---|---|
| *(no ledger)* | 0+1 — fantasy + seed | `references/step-0-1-seed.md` | the fantasy + the bare seed; **the ledger is born** |
| `top_level` | 2 — top-level design | `references/step-2-toplevel.md` | the cascade/double-lock/stats + economy + desire ladder + reactive world + frontier + **the machine** (cross-wiring core loop) |
| `casting` | 3 — casting | `references/step-3-casting.md` | the `## Casting` table (role + hook + rough sketch) |
| `npc_arcs` | 4 — NPC arcs | `references/step-4-npc-arcs.md` | one R7 brief per NPC (ONE NPC at a time) |
| `roster` | 5 — content roster | `references/step-5-roster.md` | the `## Content roster` (both tracks) |
| `authoring` | 6 — authoring | `references/beat-authoring.md` | the scaffold + green build, then one beat per turn → TOML |

The cross-cutting **run mode** (`references/run-mode.md`) wraps Steps 2–6.

## Dispatch (phase-aware — read the ledger, don't guess)
On invocation, resolve the game slug from the request, then:
1. If `games/<slug>/authoring_state.json` does **NOT** exist → **start at Step 0+1**
   (`references/step-0-1-seed.md`): lock the fantasy, plant the seed, create the ledger.
2. If it DOES exist → read **`pipeline_phase`** and continue at that step's reference (above). Do NOT
   restart from setup just because earlier work exists. (For `authoring`, do the resume-and-reconcile in
   `beat-authoring.md` first.)

Advance `pipeline_phase` as each step completes (the step references say when). A v1 ledger with no
`pipeline_phase` but a populated `plan` is in `authoring`.

## Operating rules (the run mode — full detail in `references/run-mode.md`)
- **Incremental after setup.** Never generate the game (or a whole phase) in one shot. One verified piece at
  a time. Increment ≠ slice (build order, not size — every game is the full game; slice was removed).
- **Ideate → decide → write** every increment (→ **verify green** at Step 6). The weight scales with how
  crucial the piece is.
- **Ask crucial / inform routine.** **Mode A** (`AskUserQuestion`, 2–4 options + a recommendation) only at
  a genuine fork that changes the game's identity. **Mode B** (a one-line plain-language note, then build)
  for routine, already-specified work. Not a question every beat. *Ask the crucial, inform the rest, invent
  nothing silently.*
- **Only real engine knobs.** Every option must be grounded in `COMPREHENSIVE_SYSTEM_REFERENCE.md` — never
  invent a field/trigger the engine lacks (see the engine ground-truth below).
- **Structure is stable-and-extensible:** it may grow (new location/NPC/flag), but ONLY via an explicit
  amendment done WHOLE (location → def + lock + schedule + unlock beat; NPC → schedule + open on-ramp; flag
  → reachable setter) and registered in `structure_registry`. Never a bare dangling reference.
- **Engine-forced changes bounce UP to the design book**, surfaced — never silently patched into TOML.

## Engine ground-truth (verified — so no reference reinvents a knob)
1. **Real built-in player traits:** `corruption`, `arousal`, `energy`, `hygiene`, `money` (always-on) +
   `exhibitionism`, `fitness`, `intelligence` (optional). Per-NPC: `relation`, `corruption`, `arousal`.
2. **`beauty` is NOT a raisable stat** — it's *derived read-only from worn clothing* (`worn_beauty`). Owned
   by the clothing system; raise `fitness` instead.
3. **`charisma` / `social` / a career stat are NOT built-in** — author them as **Tier-3 custom traits**
   (declare in `[player.core_traits]`, gate with the ordinary `trait` predicate). Legitimate, just not
   engine-native.
4. **No zero-choice "forced" primitive** — every canvas renders a fallback Continue. A *forced* reactive
   event = an **auto-fire capstone-shape canvas** (`priority ≥ 9`, `is_repeatable = false`, single
   Continue, no refuse/accept branch).
5. **No per-location "reactivity ceiling" attribute** — the ceiling is **author-encoded in each canvas's
   `conditions`**. Clothing gates content via the real `worn_corruption` / `corruption_level` predicates.
6. **Clothing two-part rule** (`references/systems.md`): clothing MAY gate public content + trigger ambient
   Lane 2/3 reactive events; it must **NEVER gate an NPC's escalation spine/arc**.
