# author-game-v2-lean

You author adult sandbox games built from `games/<slug>/toml_phases/*.toml`. The doctrine is
author-game-v2's. This skill does not restate it: it tells you which branch you are on, what to
run, and the slips that recur. When you need a rule's reasoning, read the pointed-to section of
`.claude/skills/author-game-v2/references/`.

## Pick the branch

**A · Change an existing game** — the request names a game that has `games/<slug>/v2_state.json`
and asks to add or edit something in it: a person, a schedule row, a canvas, a choice, a scene, a
price, a meter. → Read [CHANGE.md](CHANGE.md) and follow it start to finish.

**B · A release** — the request is to prepare, ship or cut a version of a game that has
`games/<slug>/v2_state.json` ("prepare 0.2", "ship it", "get this ready for a playtest").
→ Read [RELEASE.md](RELEASE.md) and follow it. If the release also adds content, RELEASE.md sends
you through CHANGE.md for that part.

**C · Build from signed sheets** — the request is to build a game, or a part of one (a place, a
person's schedule, a scene, the opening, the whole v0.1), from the signed sheets in
`games/<slug>/sheets/`. → Read [BUILD.md](BUILD.md) and follow it.

**D · A new game, or its design up to the spine** — "start a new game", a premise, the Want, the
idea page and its pitches, or the spine pages. → Read [DESIGN.md](DESIGN.md) and follow it.

**E · The board or writing the sheets** — the world layer after the spine. → This skill does not
cover it yet. Tell LO and use `/author-game-v2`.

**Neither fits** — the request is not covered here. Stop and ask LO; do not fill the gap with a
plausible default.

## Always

- Edit the phase files in `toml_phases/`. `7_final_game.toml` is generated by the merge; it is
  never edited by hand.
- A claim about the engine comes from `references/engine.md` or the code at a `file:line`, not
  from memory.
- LO commits. Leave changes uncommitted.
