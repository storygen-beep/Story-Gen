# piece — craft, card, show, yes

1. **Read the craft file for each area the piece touches,** in `craft/`: `craft/opening.md` for the opening, `craft/meters.md` for any meter or any act that pays one, `craft/media.md` for any card with a media spot, `craft/walk-ins.md` for a scene she walks into or someone walking in on her, `craft/body-moments.md` for a moment alone with her body (shower, dressing, towel, bed, mirror). An area with no craft file yet is listed in `LATER.md`: say so on the card, and grep `lists/COVERAGE.md` for that area.
2. **Write** the card at `games/<slug>/cards/<id>.md` from `templates/piece-card.md`. Every slot is filled; "none" is an answer, an empty slot is not. What is not on the card is not built — an author who builds from a card fills its gaps from memory without noticing (C2058). An out-of-scope line scopes out events, never the body of a moment the piece builds (`craft/body-moments.md`, step 7). `Builds:` lists every canvas, place and person id the piece adds or edits, and `sidebar:<trait>` for each sidebar item; `scripts/check.py` turns anything no approved card lists red, as "built but never approved". The `Craft:` line names each craft file read and cites every must-read id in it, or skips one with a reason: `skip C1609: no tutorial in this piece`.
3. **Check the card** before asking: `venv/bin/python .claude/skills/author-game-lean/scripts/check.py --card games/<slug> <id>`. It is red when a must-read id of a named craft file is neither cited nor skipped with a reason, when a named craft file doesn't exist, or when a card with a media spot doesn't name `craft/media.md`. Fix red before showing. Paste its verdict line into `Card checks:`. A card cannot leave out what a check needs (C2063). Numbers — word counts, explicit share, ceilings — belong to the checks at build, not to the card (C2069).
4. **Show** the file's own text, exactly, in a code block — no paraphrase. The hash covers the file, so LO sees what gets hashed. A long card goes in bites, one screen at a time, each the file's own text. End with one line of recommendation, then: "Yes, change, or drop?"
5. **Take the answer.**
   - **A plain yes:** `venv/bin/python .claude/skills/author-game-lean/scripts/approve.py games/<slug> <id> "<LO's exact words>"`, mark the piece approved in STATE.md, end with `Next step: build — <id>`.
   - **"Yes, but change X"**, "change …", "keep A, drop B": edit the card, then show only the changed lines, as before and after. LO has seen the rest. The old yes does not carry over; the new yes is recorded against the new file's hash.
   - **Drop:** remove the row from STATE.md; add a NOTES.md line in LO's words.
   - **Silence, "sounds good", an answer about something else:** not a yes. Ask again.
6. **Never build in the reply that shows the card.**

**Done when.** `approvals.json` holds this card's current hash, and STATE.md marks the piece approved.
