# Report template

The `report.md` generated by `report.js` follows this skeleton. Use this file as reference when modifying `report.js` to ensure the structure stays consistent across games.

```
# <Game Name> — Exploration Report

Generated: <ISO timestamp>
Source URL: <URL>

## Session Summary
- Sessions run: N
- Total wall-clock: Xm Ys
- Total clicks, choices, unique states, frontier size, completion status

## Engine
Detected engine: sugarcube/harlowe/chapbook/unknown, version, marshal capability

## Variable schema (inferred)
Per category table: name | type | range | samples

Categories in order: player_stat, npc_stat, body, time, flag, list, structure, scalar, misc

## NPCs detected
name | stats observed | first seen (s)

## Body / appearance traits
Variables + transitions observed

## Choice type distribution
type | count — shows what kinds of choices the game uses (branch, action_loop, quiz, payment, location)

## Economy (price observations)
Min/max price range + table of observed price choices with passage context

## Sessions
Per-session breakdown

## See also
Links to sibling files
```

The companion `mechanics.md` answers "what design patterns is this game using?" with Present/Not-detected flags for major categories (money, time, payment choices, quizzes, action-loop scenes, body transformation, multi-NPC parallel threads, location trilemmas).

The `coverage.md` is a short status: explored states vs. queued frontier.
